Filtering rows — WHERE

WHERE — basic condition

Keeps only the rows that match the condition.

SELECT name, age FROM users WHERE age > 30;

Result

nameage
Padma35
Anjali42

AND / OR — combining conditions

Chain conditions with AND (both must be true) or OR (either true).

SELECT name FROM users WHERE city = 'Visakhapatnam' AND age > 30;

Result

name
Padma

IN — match any value in a list

A cleaner alternative to chaining many OR conditions.

SELECT name, city FROM users WHERE city IN ('Visakhapatnam', 'Guntur');

Use % as a wildcard (any characters) and _ for a single character.

Aggregates — summarizing data

COUNT, SUM, AVG, MIN, MAX

Aggregate functions collapse many rows into a single value.

SELECT COUNT(*) AS total_users, AVG(age) AS average_age, MAX(age) AS oldest FROM users;

Result

GROUP BY — aggregating by category

GROUP BY

Groups rows that share a value, then applies an aggregate to each group.

SELECT city, COUNT(*) AS user_count FROM users GROUP BY city;

Result

cityuser_count
Visakhapatnam2
Vijayawada2

HAVING — filter on aggregates

WHERE filters rows; HAVING filters groups after aggregation.

SELECT city, COUNT(*) AS user_count FROM users GROUP BY city HAVING COUNT(*) > 1;

Result — only cities with more than one user

Visakhapatnam2

JOIN — combining tables

INNER JOIN

Returns rows where the join key matches in both tables. Venkatesh (id=4) and Anjali (id=5) are left out because they have no orders.

SELECT users.name, orders.amount FROM users INNER JOIN orders ON users.id = orders.user_id;

JOIN + GROUP BY — spend per user

Combining tables then summarizing is one of SQL's most common patterns.

SELECT users.name, SUM(orders.amount) AS total FROM users INNER JOIN orders ON users.id = orders.user_id GROUP BY users.name;

Aliases — renaming for clarity

AS — give columns or tables a nickname

Shortens queries and makes output labels clearer.

SELECT u.name AS customer, o.amount AS spent FROM users AS u INNER JOIN orders AS o ON u.id = o.user_id;

Changing data — INSERT, UPDATE, DELETE

INSERT — add a new row

Specify the columns, then the matching values.

INSERT INTO users (name, age, city) VALUES ('Suresh', 29, 'Tirupati');

UPDATE — change existing rows

Always include a WHERE clause — otherwise, every row gets updated.

UPDATE users SET city = 'Kakinada' WHERE name = 'Ramesh';

DELETE — remove rows

Same warning as UPDATE — a missing WHERE deletes every row.

DELETE FROM users WHERE age < 26;

Creating structure — CREATE TABLE

CREATE TABLE

Defines a new table with its columns and their data types. Constraints like PRIMARY KEY and NOT NULL control what's allowed.

CREATE TABLE products ( id INTEGER PRIMARY KEY, name TEXT NOT NULL, price DECIMAL(10, 2), created_at TIMESTAMP DEFAULT NOW() );

Common data types

Exact names vary slightly between databases, but these concepts are universal.

INTEGER -- whole numbers DECIMAL(p,s) -- exact decimals (money) TEXT / VARCHAR -- strings BOOLEAN -- true/false DATE -- calendar date TIMESTAMP -- date and time

NULL — the absence of a value

IS NULL / IS NOT NULL

NULL means "unknown". You can't compare it with = — use IS NULL instead.

SELECT * FROM orders WHERE user_id IS NOT NULL;
Tip: SQL keywords like SELECT, WHERE, and JOIN are not case-sensitive — select works just as well. Uppercase is a common convention that makes queries easier to read. End every statement with a semicolon.

Vocabulary

SQL
Structured Query Language — the standard language for reading and managing data in relational databases.
Database
An organized collection of data, usually stored on a server and accessed through queries.
Relational database
A database that stores data in tables linked by common fields. Examples: PostgreSQL, MySQL, SQLite.
Table
A grid of data made up of rows and columns. The basic unit of storage in SQL.
Row
A single record in a table. Also called a tuple.
Column
A named field that every row in a table shares. Also called an attribute.
Field
The intersection of a row and a column — a single cell of data.
Schema
The definition of a database's structure: tables, columns, data types, and relationships.
Query
A SQL statement that asks the database to do something — usually read data.
Statement
A complete SQL command, typically ending with a semicolon.
Clause
A section of a query introduced by a keyword, like WHERE, ORDER BY, or GROUP BY.
Keyword
A word reserved by SQL for a specific purpose, like SELECT or FROM.
SELECT
The clause that specifies which columns to return.
FROM
The clause that names the table(s) the data comes from.
WHERE
Filters rows based on a condition before any aggregation.
ORDER BY
Sorts the result rows by one or more columns.
ASC / DESC
Sort direction — ascending (default) or descending.
LIMIT
Caps the number of rows returned.
DISTINCT
Removes duplicate rows from the result.
Wildcard
A placeholder character used in pattern matching. % matches any sequence; _ matches a single character.
LIKE
The operator for pattern matching on text using wildcards.
IN
Operator that checks whether a value is in a given list.
BETWEEN
Operator that checks whether a value falls in a range (inclusive).
AND / OR
Logical operators for combining conditions in a WHERE clause.
NOT
Reverses a condition — NOT IN, NOT LIKE, IS NOT NULL.
NULL
Represents missing or unknown data. Compared with IS NULL, never with =.
Aggregate function
A function that collapses multiple rows into one value, like COUNT, SUM, AVG, MIN, MAX.
COUNT
Counts rows. COUNT(*) counts all; COUNT(col) counts non-NULL values.
SUM
Adds up the numeric values in a column.
AVG
Computes the average of a numeric column.
MIN / MAX
Returns the smallest or largest value in a column.
GROUP BY
Groups rows sharing a value so an aggregate can be computed per group.
HAVING
Filters groups after GROUP BY, similar to how WHERE filters rows.
Alias
A temporary name for a column or table, given with AS.
JOIN
Combines rows from two or more tables based on a related column.
INNER JOIN
Returns only rows where the join condition matches in both tables.
LEFT JOIN
Returns every row from the left table, plus matches from the right (NULL if none).
RIGHT JOIN
Mirror of LEFT JOIN — keeps every row from the right table.
FULL JOIN
Keeps every row from both tables, with NULLs where there's no match.
ON
The keyword that introduces a join's matching condition.
Foreign key
A column that refers to the primary key of another table, linking the two.
Primary key
A column (or set of columns) that uniquely identifies each row in a table.
Unique
A constraint ensuring every value in a column is different.
NOT NULL
A constraint that forbids NULL values in a column.
DEFAULT
A constraint that assigns a value automatically when none is provided.
Constraint
A rule that limits what values a column can hold.
Data type
The kind of value a column stores — integer, text, date, boolean, etc.
INSERT
The statement for adding new rows to a table.
UPDATE
The statement for changing values in existing rows.
DELETE
The statement for removing rows from a table.
CREATE TABLE
The statement that defines a new table and its columns.
DROP TABLE
The statement that deletes a table and all its data.
ALTER TABLE
Changes the structure of an existing table — adding, removing, or modifying columns.
Index
A data structure that speeds up lookups on a column, at the cost of slower writes.
Transaction
A group of statements treated as a single unit — all succeed or all are undone.
Semicolon
The standard end-of-statement character in SQL.
Comment
Non-executed text, written with -- for a single line or /* ... */ for multiple lines.
